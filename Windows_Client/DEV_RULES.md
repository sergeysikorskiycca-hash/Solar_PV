# Правила разработки Solar_PV Windows Client

Этот файл обязателен к чтению перед каждым изменением интерфейса, энергосхемы или обработчиков взаимодействия. Работать только в репозитории `sergeysikorskiycca-hash/Solar_PV`, ветка `main`.

## 1. Единый стандарт системного интерфейса

Весь системный интерфейс Windows Client использует одну общую тему. Единственное
место изменения цветов — константы класса `EnergyMapEditorSystemTheme` в
`EnergyMapEditor.cs`:

- `TextColor` — `#FFFFFF`: весь системный текст.
- `BackgroundColor` — `#3A3A3A`: фон системных контролов и область непосредственно под системным текстом.
- `SelectionColor` — `#0078D4`: наведение мыши, подсветка и выбранная строка/пункт.

Системные элементы включают кнопки, подписи, меню и пункты меню, списки,
выпадающие списки и их Popup, поля ввода, флажки, переключатели, DatePicker,
подсказки, диалоги и состояния disabled. Все их состояния должны получать
цвета через `EnergyMapEditorSystemTheme.ColorFor()` и `BrushFor()`.
Старые сохранённые `StyleOverrides`, локальные стили и палитры не должны
переопределять эти три цвета.

Не добавлять новые независимые системные цвета, цветовые словари или отдельные
настройки для конкретных системных контролов. Если новый системный контрол
требует оформления, подключать его к общей теме.

Цвета графиков, линий потоков, индикаторов данных и пользовательских объектов
энергосхемы являются цветами содержимого, а не системной темой; их не менять
при настройке общей темы.

## 2. Энергосхема: hit-testing и клики

- Прозрачный слой `EnergyMapObjectHitCanvas` содержит цели клика по SVG-объектам. Его `IsHitTestVisible` должен быть `true` сразу после запуска в рабочем режиме.
- В рабочем режиме клик по домику открывает статистику без предварительного входа в администратора.
- В режиме перемещения объектов `_energyMapEditMode` слой целей объектов должен отключаться (`IsHitTestVisible = false`), чтобы не перехватывать перетаскивание.
- После выхода из режима перемещения слой целей объектов должен включаться снова.
- `EnergyMapItemsCanvas` и его пользовательские элементы остаются доступны для редактирования только в режиме администратора.
- Не путать два слоя: `EnergyMapObjectHitCanvas` обрабатывает клики по базовым SVG-объектам; `EnergyMapItemsCanvas` — пользовательские элементы энергосхемы.
- Проверять запуск сразу в обычном режиме: домик должен нажиматься без предварительного переключения в режим администратора. Переключение режимов не должно быть условием инициализации hit-testing.

## 3. Перед каждым обновлением

1. Прочитать этот файл.
2. Проверить текущий `main` и последние коммиты, не полагаться на старый локальный контекст.
3. Проверить, что системные надписи имеют белый текст и тёмно-серый фон, включая программно создаваемые окна.
4. Проверить независимость цветов объектов энергосхемы от системной темы.
5. Проверить клики по домику сразу после чистого запуска в рабочем режиме.
6. Проверить, что режим перемещения отключает прозрачные цели клика, а выход из него восстанавливает их.
7. Менять только необходимые файлы; не создавать ветки и дополнительные файлы без прямого разрешения пользователя (кроме явно запрошенной документации).
8. Не запускать сборку, тесты или Actions без разрешения пользователя. Если пользователь сам запускает сборку и она падает — самостоятельно изучить GitHub Actions и логи, найти причину и исправить её в `main`, не просить пользователя присылать лог, если он доступен.

## 4. История обнаруженной ошибки

В версии с окном статистики домика `EnergyMapObjectHitCanvas` был задан в XAML как `IsHitTestVisible="False"`, а `EnergyMapItemsCanvas` оставался включённым по умолчанию. `UpdateEnergyMapHitTesting()` вызывался только при переключении режима администратора. Поэтому при первом запуске слои кликов имели неверное состояние: верхний слой пользовательских элементов мог перехватывать мышь, а слой SVG-целей был выключен. Вход/выход из администратора вызывал обновление hit-testing и случайно исправлял состояние. Исправление: включить SVG hit-canvas в XAML, вызвать `UpdateEnergyMapHitTesting()` сразу после `BuildEnergyMapItems()` в конструкторе и централизованно задавать `EnergyMapObjectHitCanvas.IsHitTestVisible = !_energyMapEditMode`, `EnergyMapItemsCanvas.IsHitTestVisible = _isAdminMode`.

В предыдущей версии окно статистики имело собственную сине-серую палитру и цветные подписи, что нарушало единый системный стандарт. Для всех динамических окон применять белый текст и фон `#3A3A3A` непосредственно под текстом.


## Единая системная тема Windows Client

Все системные цвета централизованы в классе `EnergyMapEditorSystemTheme`
(файл `EnergyMapEditor.cs`). Менять их разрешено только в трёх константах:

- `TextColor` — основной системный текст: `#FFFFFF`.
- `BackgroundColor` — фон системных элементов и непосредственно под системным текстом: `#3A3A3A`.
- `SelectionColor` — наведение, подсветка и выбранная строка: `#0078D4`.

Системные кнопки, меню, пункты списков, ComboBox/Popup, поля ввода,
подсказки и диалоги получают цвета через `ColorFor()` и `BrushFor()`.
Не создавать для них независимые цветовые настройки, локальные цветовые
переопределения или отдельные палитры в XAML и code-behind. Старые сохранённые
системные `StyleOverrides` не должны менять общую тему.

Цвета графиков, энергосхемы и пользовательских объектов данных остаются
самостоятельными и не относятся к системной теме.

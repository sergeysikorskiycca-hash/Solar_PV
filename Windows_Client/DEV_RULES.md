# Правила разработки Solar_PV Windows Client

Работать только в репозитории `sergeysikorskiycca-hash/Solar_PV`, ветка `main`.

## 1. Единая системная тема

Единственный источник системных цветов — `EnergyMapEditorSystemTheme` в `EnergyMapEditor.cs`. Управление цветами выполняется только через три константы:

- `TextColor` — белый `#FFFFFF`.
- `BackgroundColor` — тёмно-серый `#3A3A3A`.
- `SelectionColor` — синий `#0078D4`.

Все системные окна и контролы используют `ColorFor()`, `BrushFor()` и `Apply()`: окна, панели, подписи, кнопки, меню, поля ввода, списки, ComboBox и их Popup, DatePicker/Calendar, подсказки, диалоги, флажки и переключатели. Обычное и неактивное состояние — белый текст на сером фоне; hover, pressed, highlighted и selected — синий фон с белым текстом.

Запрещено добавлять отдельные системные палитры, варианты тем, настройки системных цветов, литералы системных цветов в XAML/code-behind и локальные стили Popup/ComboBox/ListBox, расходящиеся с центральной темой. Системные цвета не сохраняются в `ClientSettings`.

Цвета телеметрии, графиков, линий потоков, индикаторов, SVG-энергосхемы, пользовательских объектов и предпросмотра их оформления — содержимое, а не системная тема. Они остаются независимыми и исключаются из системного обхода.

## 2. Энергосхема: hit-testing и клики

- `EnergyMapObjectHitCanvas` содержит цели клика по SVG-объектам и включён сразу после запуска в рабочем режиме.
- В рабочем режиме клик по домику открывает статистику без предварительного входа в администратора.
- В режиме перемещения `_energyMapEditMode` слой целей отключается, чтобы не перехватывать перетаскивание.
- После выхода из режима перемещения слой целей снова включается.
- `EnergyMapItemsCanvas` и пользовательские элементы доступны для редактирования только в режиме администратора.
- `EnergyMapObjectHitCanvas` обрабатывает клики по базовым SVG-объектам; `EnergyMapItemsCanvas` — пользовательские элементы.

## 3. Перед каждым обновлением

1. Прочитать этот файл и проверить текущую ветку `main`.
2. Проверить, что системные элементы используют только три централизованных цвета.
3. Проверить Popup и состояния hover/pressed/selected.
4. Проверить независимость цветов графиков, телеметрии и пользовательских объектов энергосхемы.
5. Проверить клики по домику сразу после запуска и переключение режима перемещения.
6. Менять только необходимые файлы; не создавать ветки и дополнительные файлы без разрешения.
7. Не запускать сборку, тесты или Actions без разрешения пользователя. Если пользователь запускает сборку и она падает — изучить доступные GitHub Actions и логи и исправить причину в `main`.

SOLAR PV ADMIN DEMO
===================

Назначение
----------
В корне репозитория находятся три самостоятельных демонстрационных интерфейса веб-админки Solar PV:

- variant-a.html — промышленная панель: тёмная тема, крупные показатели и диагностические блоки.
- variant-b.html — минималистичная панель: светлая тема, карточки и простая навигация.
- variant-c.html — SCADA: техническая компоновка и мнемосхема с условной визуализацией потоков.

Откройте любой HTML-файл непосредственно в браузере Windows. Внешние библиотеки и сервер для демонстрации не требуются.

ВАЖНО: ДЕМО-РЕЖИМ
----------------
Все показания, графики, состояния узлов и доступные Wi-Fi сети являются тестовыми примерами. Физическое оборудование не опрашивается. Команды ESP32/ESP8266 не отправляются, параметры RTC и Wi-Fi не изменяют реальную конфигурацию. Анимация на мнемосхеме обозначает только условный поток данных.

Архитектурная модель
-------------------
Целевая система:
- ESP8266 Gateway — получение телеметрии двух солнечных строк.
- ESP32 CPU — центральный контроллер, Wi-Fi, веб-интерфейс, TFT и будущий API.
- INA226 — два независимых измерительных канала: string-1 и string-2.
- DS3231 — часы реального времени.

В демонстрационных страницах используются две фиксированные солнечные строки. Третья и последующие строки не поддерживаются. У каждой строки свои напряжение, ток, мощность, калибровки и накопленная энергия. Исключение строки из общей суммы не должно сбрасывать её индивидуальную энергию.

Показатели энергии
------------------
- Внутренний целочисленный формат хранения: Wh.
- Представление для пользователя: кВт·ч.
- Интервал сохранения в интерфейсе: от 5 до 60 минут.
- Сброс отображаемого периода и полный сброс накопленной энергии — разные операции.
- Предусмотрен выбор дня ежемесячного сброса отображаемого периода.

Слои данных и подключение реального API
---------------------------------------
Текущая реализация намеренно автономна: каждый HTML содержит собственные CSS и JavaScript, а тестовые значения заданы непосредственно в демонстрационном интерфейсе. Реального API-адаптера в этих макетах ещё нет.

Рекомендуемая граница для следующего этапа интеграции:
1. Слой источника данных должен предоставлять единый объект телеметрии независимо от дизайна.
2. Демонстрационный адаптер должен формировать этот объект из тестового набора.
3. Будущий адаптер ESP32 должен получать тот же набор полей из API, не меняя компоненты отображения.

Рекомендуемая логическая схема данных (контракт для будущей интеграции):
{
  "source": "demo",
  "timestamp": "ISO-8601",
  "system": {
    "gateway": "online|offline|unknown",
    "cpu": "online|offline|unknown",
    "rtc": "ok|warning|unknown",
    "wifi": {
      "ap": "on|off|unknown",
      "station": "connected|disconnected|unknown"
    }
  },
  "strings": [
    {
      "id": "string-1",
      "sensor": "INA226",
      "voltage_V": 186.4,
      "current_A": 5.82,
      "power_W": 1084,
      "energy_Wh": 7214600,
      "calibration": {
        "voltage": 1.0,
        "current": 1.15
      },
      "includedInTotal": true
    },
    {
      "id": "string-2",
      "sensor": "INA226",
      "voltage_V": 182.1,
      "current_A": 4.16,
      "power_W": 758,
      "energy_Wh": 5631400,
      "calibration": {
        "voltage": 1.0,
        "current": 1.15
      },
      "includedInTotal": true
    }
  ],
  "energy": {
    "saveIntervalMinutes": 15,
    "monthlyDisplayResetDay": 1
  }
}

Единицы и идентификаторы
------------------------
- voltage_V — напряжение, вольты.
- current_A — ток, амперы.
- power_W — мощность, ватты.
- energy_Wh — накопленная энергия, целое число ватт-часов.
- string-1 и string-2 — постоянные идентификаторы источников.
- includedInTotal — участие строки в суммарном отображении.

Будущие расширения
------------------
В перспективе модель можно расширить отдельными источниками для аккумулятора, потребления из сети и генерации инвертора. Эти источники не реализованы как действующие функции в текущем демо.

Ограничения текущей версии
--------------------------
- Нет связи с ESP32, ESP8266, INA226 или DS3231.
- Нет реального сканирования Wi-Fi, записи настроек и установки времени.
- Элементы управления демонстрируют сценарии и подтверждения, но не сохраняют конфигурацию контроллера.
- Данные графиков статические и демонстрационные.
- Варианты автономны и содержат собственные стили и скрипты; общий runtime-адаптер данных ещё предстоит вынести при интеграции.
